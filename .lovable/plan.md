# Nippon — سوق أجهزة التعدين المستعملة

منصة عربية (RTL) بتصميم ثلاثي الأبعاد لبيع وشراء أجهزة تعدين الكريبتو المستعملة، مع دردشة بين البائع والمشتري، ونظام حماية المشتري (حجز المبلغ)، ومحفظة كريبتو، وتحقق من الهوية.

## الهوية البصرية
- اسم الموقع: **Nippon**
- واجهة عربية بالكامل مع اتجاه RTL وخطوط عربية عصرية.
- طابع 3D: بطاقات بعمق وظلال، إضاءة نيون هادئة، دوران خفيف للبطاقات عند التمرير، خلفية شبكية متحركة، وأزرار بارزة. سأعرض 3 اتجاهات تصميم مرئية للاختيار قبل البناء الكامل.

## الصفحات
- الرئيسية: عرض بطولي 3D، أحدث الأجهزة، كيف يعمل نظام الضمان، ثقة/إحصاءات.
- السوق: قائمة الأجهزة مع فلاتر (النوع، الهاش ريت، السعر، الحالة، الضمان).
- صفحة الجهاز: صور، مواصفات، السعر، مدة الضمان، بيانات البائع وتقييمه، زر "شراء بحماية المشتري" وزر "دردشة".
- إضافة عرض: نموذج إلزامي — العنوان، النوع، الهاش ريت، الاستهلاك، الحالة، **السعر (إجباري)**، **الضمان (إجباري)**، الوصف، الصور. لا يُنشر بدون هذه الحقول ولا بدون توثيق الهوية.
- الدردشة: محادثات فورية بين المشتري والبائع مرتبطة بكل عرض.
- المحفظة: الرصيد، الإيداع، السحب، سجل العمليات، المبالغ المحجوزة في الضمان.
- الحساب/التحقق: رفع صورة الهوية + سيلفي، حالة الطلب (قيد المراجعة/مقبول/مرفوض).
- الطلبات: تتبع حالة الصفقة (بانتظار الدفع → المبلغ محجوز → تم الشحن → تم الاستلام → تحرير المبلغ) مع فتح نزاع.
- لوحة الإدارة: مراجعة طلبات التحقق، إدارة النزاعات، تحرير أو إرجاع المبالغ.

## نظام حماية المشتري (Escrow)
1. المشتري يدفع → يُحجز المبلغ في المنصة (حساب ضمان داخلي).
2. البائع يشحن ويضيف بيانات الشحن.
3. المشتري يؤكد الاستلام → يُحرَّر المبلغ للبائع بعد خصم العمولة.
4. عند وجود مشكلة: فتح نزاع خلال مدة محددة والإدارة تقرر التحرير أو الاسترجاع.

## المحفظة والدفع بالكريبتو
- المرحلة الأولى: دفاتر المحفظة والضمان داخل قاعدة البيانات (رصيد، إيداع، حجز، تحرير، سحب) — وهي البنية التي يعمل عليها الموقع فعليًا.
- الربط الحقيقي بالبلوكشين يتم عبر مزود دفع كريبتو (مثل NOWPayments أو Coinbase Commerce): إنشاء عناوين إيداع، تأكيد المدفوعات عبر Webhook، وطلبات السحب. هذا يتطلب حسابًا لديك ومفاتيح API — سأطلبها منك بشكل آمن عند الوصول لهذه الخطوة، وحتى ذلك الحين تعمل المحفظة بالدفاتر الداخلية دون كسر أي شيء.

## التحقق من الهوية
رفع المستندات إلى تخزين خاص، حالة `pending/approved/rejected`، والمشرف يراجع من لوحة الإدارة. النشر والبيع مقصوران على الحسابات الموثقة.

## التفاصيل التقنية
- تفعيل Lovable Cloud: قاعدة بيانات + مصادقة (بريد/كلمة مرور) + تخزين للصور والمستندات + دوال خادم.
- الجداول: `profiles`، `user_roles` (جدول أدوار منفصل + دالة `has_role`)، `kyc_submissions`، `listings`، `conversations`، `messages`، `orders`، `wallets`، `wallet_transactions`، `escrow_holds`، `disputes`، `reviews`.
- RLS على كل جدول مع GRANTs صريحة؛ الملفات الحساسة (الهوية) في bucket خاص.
- كل عمليات المال (حجز/تحرير/استرجاع/سحب) تتم داخل دوال خادم مع تحقق من الصلاحيات، لا من المتصفح.
- الدردشة عبر Realtime.
- التحقق من المدخلات بـ zod على العميل والخادم.

## خطة التنفيذ
1. اتجاهات التصميم 3D → اختيارك.
2. تفعيل Lovable Cloud + المخطط والسياسات + بيانات تجريبية.
3. المصادقة والملف الشخصي والتحقق من الهوية.
4. السوق + صفحة الجهاز + إضافة عرض.
5. الدردشة الفورية.
6. المحفظة + الطلبات + الضمان + النزاعات.
7. لوحة الإدارة.
8. ربط مزود الدفع بالكريبتو (بعد توفير المفاتيح).
